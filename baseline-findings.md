# Baseline Metrics & Key Findings (Homepage)

Based on the PageSpeed Insights baseline for the primary page (apnews.com), the site suffers heavily from third-party bloat and unoptimized media delivery. Here are the 5 worst performing areas identified:

### Finding 1: Severe Main Thread Blocking from Third-Party Scripts
* **How this affects users:** When users try to scroll the news feed or tap an article, the page freezes or stutters. This unresponsiveness is highly frustrating and can cause users to abandon the site.
* **Which metric(s) are affected:** Total Blocking Time (TBT), Interaction to Next Paint (INP).
* **Most likely cause:** Heavy JavaScript execution from programmatic advertising (header bidding), tracking pixels, and analytics loading synchronously on the main thread during the initial page load.
* **Likely solution:** Defer non-critical third-party JavaScript using `defer` or `async` attributes. Move resource-intensive third-party trackers to a Web Worker (using a library like Partytown) to free up the main UI thread.

### Finding 2: Delayed Delivery of the Primary Content
* **How this affects users:** Users stare at a blank screen or a partially loaded page for too long before the main headline and hero image appear, making the site feel sluggish.
* **Which metric(s) are affected:** Largest Contentful Paint (LCP), First Contentful Paint (FCP).
* **Most likely cause:** The main hero image (LCP element) is not prioritized. It is likely competing for bandwidth with render-blocking CSS/JS, lacking preloading, or being served in legacy formats (like large JPEGs) instead of next-gen formats.
* **Likely solution:** Add a `<link rel="preload" fetchpriority="high">` tag for the hero image. Convert top-of-fold images to modern formats like WebP or AVIF and ensure critical CSS is inlined.

### Finding 3: Unstable Layouts While Reading (Jumping Content)
* **How this affects users:** As users begin reading the top headlines, the text suddenly jumps down the screen. This causes users to lose their place or accidentally tap the wrong link, creating a jarring user experience.
* **Which metric(s) are affected:** Cumulative Layout Shift (CLS).
* **Most likely cause:** Dynamic ad banners and related-article widgets are injected into the DOM after the text has already rendered, and no fixed space was reserved for them beforehand.
* **Likely solution:** Assign static aspect ratios or CSS `min-height` values to all ad slots and media containers before they load. This reserves the exact amount of space needed, preventing the text from shifting when the ad finally renders.

### Finding 4: Excessive DOM Size
* **How this affects users:** The browser struggles to calculate the layout, which drains mobile battery life and causes slow, choppy rendering on lower-end mobile devices.
* **Which metric(s) are affected:** Time to Interactive (TTI), Total Blocking Time (TBT).
* **Most likely cause:** Deeply nested HTML structures generated by complex mega-menus, infinite scrolling components, and hidden UI elements that are rendered in the DOM even when off-screen.
* **Likely solution:** Implement "virtualization" or windowing for long lists of articles (only rendering what is in the viewport). Simplify the CSS/HTML tree depth and lazy-load hidden components like off-canvas menus until the user interacts with them.

### Finding 5: Flash of Invisible Text (FOIT)
* **How this affects users:** The page structure loads, but the actual text of the headlines remains invisible for several seconds, completely preventing the user from consuming the news.
* **Which metric(s) are affected:** First Contentful Paint (FCP), Largest Contentful Paint (LCP).
* **Most likely cause:** Custom web fonts (e.g., AP's specific branding typography) are blocking the render. The browser hides the text until the large font files finish downloading.
* **Likely solution:** Add `font-display: swap` to all `@font-face` declarations. This forces the browser to immediately display a fallback system font (like Arial or Georgia) and swap it to the custom font once it loads, allowing users to read the news instantly.
